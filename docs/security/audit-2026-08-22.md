# EduCore — Security Audit (2026-08-22)

Defensive review; nothing exploited destructively. Severity: Critical/High/Medium/Low.

## Critical
1. **Unauthenticated bundle mutation** — `PUT /api/bundles/{id}`, `POST /api/bundles/{id}/items`,
   `DELETE /api/bundles/{id}/items/{courseId}` have no auth attributes. Anonymous attackers can
   rename/reprice any bundle and change its courses. (BundlesController.cs)
2. **Payment endpoints without ownership checks** — `GET /api/payments/{id}` is anonymous (leaks
   TransactionId, IdempotencyKey, amounts). Create/succeed/fail/expire accept any payment/order from
   any authenticated user. (PaymentsController.cs)
3. **Self-service payment success** — `PUT /api/payments/{id}/checkOut-succeed` trusts a client-supplied
   TransactionId; no gateway verification; combined with #2 → free enrollments for any order.
4. **Hardcoded DB credentials in source** — `clsDataAccessSettings.cs` contains `sa`/`sa123456`.
5. **Secrets in `.env`** — JWT signing key + API key in working tree; weak JWT secret for HS256.
   `.env` is gitignored now; verify it was never pushed and rotate regardless.

## High
6. **Progress/certificate without enrollment checks** — any authenticated user can mark any lesson
   complete and generate certificates (after C1/C8 fixes this becomes the main cheat path).
7. **Audit trail stores `HttpContext.Connection.Id`** (a GUID) instead of the client IP in all
   controller audit calls → forensic value lost. (ExceptionMiddleware uses the correct property.)
8. **No publish endpoints for courses/lessons** — availability controlled only at DB level.

## Medium
9. **User enumeration** — anonymous `GET /api/users/email-exists`.
10. **Rate limiting gaps** — only login/refresh limited (5/min/IP). Registration, email-exists,
    discount lookups, certificate generation unlimited. 429 middleware writes a login-specific message
    for all endpoints and may write after response start.
11. **Certificate DoS** — PDF+QR written to disk per request, no dedupe/persistence.
12. **JWT lifetime/revocation** — role changes and deactivation don't invalidate live access tokens
    (30-min window). No jti/revocation list. Acceptable if documented; otherwise add revocation.
13. **Email change without uniqueness precheck** — DB unique violation surfaces as 500 with details
    logged (info disclosure via Logs table to admins only — contained).
14. **`BundleExists` hardcoded `B.Id = 1`** — existence checks for bundle item endpoints always test
    bundle 1 (logic bug with minor security flavor: wrong 404/allow decisions).

## Low / Positive findings
- Passwords: BCrypt WF12 — good. Refresh tokens hashed — good. Password policy strong.
- SQL: parameterized everywhere; no injection found. (One interpolated WHERE clause uses only
  compile-time constants.)
- CORS restricted to two localhost dev origins; Swagger dev-only; HTTPS redirection enabled.
- No CSRF surface (bearer tokens only). No file upload endpoints.
- Exception middleware hides internal errors from clients (generic 500) but stores stack traces in DB
  Logs (admin-only endpoints) — acceptable.

## Recommendations (order)
1. Add auth+ownership to bundle and payment endpoints (Critical 1–3).
2. Move connection string to env config; rotate `sa` password; rotate JWT secret; add `.env.example`.
3. Enrollment checks on progress/certificate endpoints.
4. Fix audit IP capture (use `RemoteIpAddress`).
5. Rate-limit registration + certificate endpoints; generic 429 message.
6. Document/decide token-revocation posture.
